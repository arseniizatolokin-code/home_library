# home_library

Консольна програма мовою Dart для лабораторної роботи 1 («Функції та обробка
колекцій»). Предметна область, варіант 1: **домашня бібліотека**. Програма
розбирає вхідні рядки про книги, перевіряє значення на допустимі діапазони,
групує й сортує книги та друкує звіт.

Основна сутність: книга (автор, назва, рік видання, кількість сторінок, жанр,
дата прочитання).

## Запуск

```
dart pub get
dart run
dart analyze
dart format .
```

Потрібен Dart SDK 3.13 або новіший. Перевірено: `dart analyze` без зауважень,
`dart format .` нічого не змінює.

## Структура

```
bin/home_library.dart      точка входу: збирає результат і друкує його
lib/book_parser.dart       тип Book, розбір рядка та дати
lib/book_validator.dart    перевірка діапазонів значень
lib/book_analytics.dart    конвеєри where / map / fold
lib/book_grouping.dart     групування за жанром і агрегати груп
lib/book_sorting.dart      сортування за двома критеріями
lib/book_report.dart       текстовий звіт на StringBuffer
lib/book_closures.dart     замикання: фабрика предикатів, лічильник
lib/book_text.dart         регулярний вираз, маскування дати
lib/book_dates.dart        арифметика дат
lib/sample_data.dart       вхідні дані (23 рядки, з них 4 пошкоджені)
analysis_options.yaml      правила аналізатора
```

Логіку винесено в `lib/`, а `bin/` лише викликає її й друкує результат: так
функції можна буде перевіряти модульними тестами (вимога з лабораторної
роботи 3) без запуску програми.

## Обґрунтування рішень

### Типи даних

- **Запис (record) замість класу.** Книга описана псевдонімом
  `typedef Book = ({String author, ...})`. Класи в цій роботі не потрібні:
  це набір значень без поведінки, а запис має структурну рівність і
  короткий синтаксис. Класи з'являються в лабораторній роботі 2.
- **`DateTime? readDate`.** Порожня дата означає «ще не прочитано»; це
  допустиме значення, тому поле nullable, а не рядок із спеціальним
  значенням.
- **Результат розбору — запис `({Book? book, String? error})`.** Він несе
  або книгу, або опис помилки. Виняток не використовується: пошкоджений
  рядок — очікувана ситуація, а не виняткова.
- **`Map<String, GenreStats>` для агрегатів.** Ключ — жанр, значення —
  запис `({int count, double averagePages})`.
- **`List` для впорядкованих даних, `Map` для групування.** `Set` не
  потрібен: унікальність значень не вимагається. Альтернатива `Map` для
  групування — пакет `collection` із `groupBy`; не використано, щоб не
  додавати залежність заради десяти рядків коду.

### Розбір і перевірка

- `int.tryParse` і `DateTime.tryParse` замість `parse` у `try/catch`: помилка
  формату очікувана, а `tryParse` повертає `null` без винятку.
- `DateTime.tryParse('2025-13-45')` не повертає `null`, а зсуває дату на
  наступний рік. Тому `parseStrictDate` спершу перевіряє форму запису
  регулярним виразом, а потім звіряє розібрану дату з вихідним текстом.
- Поточна дата передається в `validateBook` і `readAges` параметром
  `today`. `DateTime.now()` не можна використати як значення параметра за
  замовчуванням (воно має бути константою часу компіляції), а передача
  ззовні робить функції детермінованими.

### Конвеєри та цикли

Агрегація виконана конвеєрами `where` → `map` → `fold`
(`readBooks`, `titlesByGenre`, `totalPagesRead`, `statsByGenre`).
Цикли `for` свідомо залишено там, де вони читаються краще:
`groupByGenre` (накопичення в `Map` через `putIfAbsent`), `buildReport`
(послідовне заповнення `StringBuffer`) і друк результатів у `main`.

### Замикання

- `longerThan(minPages)` повертає предикат; замикання захоплює параметр
  `minPages` і зберігає його, поки існує посилання на предикат.
- `createCounter()` повертає лічильник; замикання захоплює локальну змінну
  `count`, яка живе, доки живе функція, і кожен лічильник має власну копію.

### Рядки, регулярні вирази, дати

- Звіт збирається в `StringBuffer`, а не конкатенацією `+=` у циклі.
- Шаблон дати записано сирим рядком `r'...'` з іменованими групами
  `year`, `month`, `day`, щоб не покладатися на номери груп.
- Маскування дати виконано через `replaceAllMapped`.
- Вік запису в днях рахується через `DateTime.difference` і `Duration`. Дати
  попередньо приводяться до UTC-опівночі, щоб перехід на літній час не
  зменшував різницю на добу.

## Залежності з pub.dev

Залежностей часу виконання немає. У `dev_dependencies` залишено лише те, що
додає шаблон `dart create -t console`:

| Пакет | Навіщо | Альтернативи |
|---|---|---|
| `lints` | набір правил для `analysis_options.yaml` (`recommended.yaml`), вимога методички | `flutter_lints` (розрахований на Flutter), `very_good_analysis` (суворіший, але нав'язує додаткові правила) |
| `test` | запуск модульних тестів; у цій роботі не використовується, потрібен з лабораторної роботи 3 | `package:test` є стандартним вибором для Dart; альтернатив у проєкті не розглядалося |

Пакет `collection` не підключено: `firstOrNull` і `lastOrNull` доступні в
`dart:core` з Dart 3.0, а групування реалізовано власною функцією.

## Вживання `!`, `late`, `dynamic` і приведення типів

- Оператор `!`: **не використовується.**
- Ключове слово `late`: **не використовується.**
- Тип `dynamic`: **не використовується.** Налаштування, які могли б бути
  `Map<String, dynamic>`, не потрібні в цій програмі.
- Приведення `match as RegExpMatch` у `maskDate`. `String.replaceAllMapped`
  оголошує параметр функції типу `Match`, а метод `namedGroup` є лише в
  `RegExpMatch`. Для шаблону типу `RegExp` Dart завжди повертає саме
  `RegExpMatch`, тому приведення безпечне.

## Налаштування аналізатора

`analysis_options.yaml` підключає `package:lints/recommended.yaml` і додає
суворі режими `strict-casts`, `strict-raw-types`, `strict-inference`, а також
правила `public_member_api_docs`, `prefer_final_locals`,
`prefer_final_in_for_each`, `avoid_positional_boolean_parameters`,
`unnecessary_lambdas`.
